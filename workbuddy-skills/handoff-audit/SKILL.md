# 接手审核（从别的对话里把提示词捞出来审）

## 这个 skill 解决什么

用户在另一个对话里让 AI 生成了一版提示词，跑到这个对话只说一句「审一下最近那条」。
问题是：**跨对话的正文读不到**，`conversation_search` 也搜不到。

但对方对话通常把提示词落成了文件。本 skill 的任务就是：**把文件捞出来 → 反推它对应哪条素材 → 实测 → 审 → 出一版优化稿。**

不要求用户重新粘贴。找不到文件时才回退到「请把正文贴过来」，并且只问这一句，不要空转。

---

## 第一步：定位提示词文件

按修改时间倒序找候选，不要只找一个：

```bash
# 最近改动过的提示词文件（含脚本落盘的中间产物）
find "C:/Users/TTT/WorkBuddy" "C:/Users/TTT/.workbuddy" "D:/WorkBuddy资料" "C:/Users/TTT/Desktop" \
  -maxdepth 6 -type f \( -iname "*last_prompt*" -o -iname "*patched*" -o -iname "*提示词*.md" -o -iname "*提示词*.txt" -o -iname "*prompt*.md" \) \
  -printf "%T@ %p\n" 2>/dev/null | sort -rn | head -12

# 最近活跃的对话工作区（目录名就是时间戳，最新的在最前）
ls -dt "C:/Users/TTT/WorkBuddy"/*/ 2>/dev/null | head -5
```

判读：

- `C:/Users/TTT/WorkBuddy/<时间戳>/` 每个目录是一次对话的工作区，最新的 = 最近那条对话
- `_audit_last_prompt.md` 是审计脚本的输入（即待审原文）
- `_audit_patched.md` 是脚本补过结构字段的版本（**通常比原文更差**，因为它会往里塞「画幅/起幅/声音」这类编辑任务用不上的字段）
- **优先审 `_audit_last_prompt.md`**，把 `_audit_patched` 的差异当参考，不要当答案

找不到就停，只回一句：「我这边读不到那条对话的正文，把提示词贴过来，或者让它存到 `D:\WorkBuddy资料\鞋款替换审核\待审\` 下。」

## 第二步：反推它对应哪条素材

提示词里几乎总会露线索，按可靠性排序：

1. **时长 + 画幅**（「8秒竖屏」「14.22秒」）——最硬的指纹，直接对 ffprobe
2. **背景物件**（「银色菱格纹抽屉柜」「水泥墩」「百叶墙」）——用来在候选里挑
3. **动作时序**（「0–2.6秒一只靴加一只赤脚」）——反过来验证你挑对了没有
4. **商品信息**（颜色、鞋型）——用来找对应的商品图目录

匹配方法：

```bash
# 列出候选视频的时长/分辨率，逐个对
for f in "C:/Users/TTT/Desktop/同行视频"/*/*/*.mp4; do
  echo "$f"; ffmpeg -hide_banner -i "$f" 2>&1 | grep -E "Duration|Stream #0:0" | head -2
done
```

**匹配上之后必须回头验一遍**，至少核三条线索（时长、画幅、背景或动作）。只对上一两条就下结论，很容易把第 2 条片子的提示词套到第 3 条上——这种串片一旦发生，后面所有判断都会错。

## 第三步：实测素材（不可跳过）

```bash
ffmpeg -hide_banner -i "<video>" 2>&1 | grep -E "Duration|Stream"
mkdir -p "<out>"; ffmpeg -hide_banner -loglevel error -i "<video>" -vf "fps=1,scale=360:-1" "<out>/f_%02d.jpg"
ffmpeg -hide_banner -loglevel error -i "<out>/f_%02d.jpg" -vf "tile=5x4" -frames:v 1 "<out>/sheet.jpg"
ffmpeg -hide_banner -i "<video>" -vf "select='gt(scene,0.08)',metadata=print:file=-" -an -f null - 2>/dev/null | grep pts_time
```

必查六项并列表对照：时长/画幅/帧率、主体像素尺寸、被裁切与遮挡情况、主体最清楚的秒、**是否真有水印**、镜头切换点。

同时逐条核对提示词里的**事实陈述**：原物颜色、材质、跟高、有哪些部件、剪辑点在第几秒。这类描述很多是从别的片子串过来的，错一条就会让整份提示词的「差异判断」跑偏。

## 第四步：审核判断

加载 `prompt-audit` skill，走它的 A1（能力边界阈值）、A2（结构体检）、A3（同结构替换陷阱）、A4（三类高频错误写法）。

本场景最常见的五个问题，按命中率：

1. **原物描述抄了另一条片子**（颜色/材质错）。后果是差异判断错位——你以为在改大的，其实差异很小，模型只微调颜色就交差。
2. **同结构重合 ≥3 处**却按「替换清单」写。必须改成「旧的要死 → 新的要生 → 看得见的差别」。
3. **把资源压在只出现不到 20% 时间的部件上**（后拉链、鞋底纹路）。这种部件写了也白写，要么切专项片段，要么降级为「只求最显眼的那一个零件」。
4. **开头塞了「画幅/机位/起幅/焦点」段落**。编辑任务里机位是原片给的，复述会让模型想重绘画面；更糟的是它常和提示词后文的「硬切保持不变」自相矛盾。
5. **`【图1】` 不是 `@图片1`**，素材根本没绑上。

另外：对方若跑过格式审计脚本并报「全部通过」，要当面指出——**脚本查的是字段齐不齐，不是物理上做不做得到**。格式满分和换鞋成功是两件事。

## 第五步：输出

固定五段，不要自由发挥：

1. **一句话说明怎么找到的**（路径 + 判断它对应哪条片子 + 一句「核了哪三条线索」）
2. **实测对表**：项目 / 实测 / 提示词写的，错的地方直接标出来
3. **P0 问题**，最多三条，每条写「现象 → 根因 → 改法」
4. **一整条优化版提示词**（代码块，可直接复制，不拆分、不给「主提示词+追加句」）
5. **看结果时盯哪一个信号**：只给一个判据，就是「这一个东西出现了，就说明换成了」的那个东西

交付偏好（沿用本用户习惯）：用无限画布拖图，所以要给「拖哪几张、每张管什么」；提示词要一整条；不写「建议更具体一些」这类空话。

## 第六步：归档

审完把原件改名归档，避免下次重复审：

```bash
mv "<dir>/_audit_last_prompt.md" "<dir>/_audit_last_prompt_已审_<YYYYMMDD>.md"
```

不要删除原件，用户可能需要回看上一版为什么失败。

---

## 常见误判

- 拿 `_audit_patched.md` 当最终稿审 → 它多了「声音/起幅」这类无用字段，审出来的结论会偏
- 只凭提示词里的颜色描述判断原物 → 必须回原片看一眼，颜色是最容易被串错的一项
- 找到多个候选就直接选最新的 → 最新那份可能是别的任务的，先验时长和画幅
- 用户说「审一下」就只给问题清单 → 本用户要的是能直接粘走的一整条优化稿
