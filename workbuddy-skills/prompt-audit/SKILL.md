# 提示词 / 文案审核

## 核心立场

审核不是润色。用户拿来的文本通常**内容没错、框架错了**。多数「生成不对」的根因不在措辞，而在三件事：素材本身不支撑这个要求、任务超出模型能力边界、提示词的结构让模型选择了最省力的解。

因此：**先核素材，再判可行性，最后才改文字。** 只读文本就下判断，等于瞎审。

禁止为了显得专业而罗列无关的措辞建议。原文没问题的地方，直接说没问题。

---

## 第一步：路由

| 输入特征 | 走 |
|---|---|
| 带 `@图片/@视频` 或【】分节的生成提示词、讲「换鞋/换人/换背景/生成不对」 | 流程 A：生成提示词审核 |
| 抖音/千川投放文案、商品标题、卖点话术、评论区引导语 | 流程 B：投放文案合规审核 |

两类混在一起（例：一条带货视频的提示词里含广告用语），以 A 为主，B 作为附加检查项附在报告末尾。

## 流程 A：生成提示词审核（五步）

### A0 素材实测（不可跳过）

提示词里写的一切，都要拿素材去对。有视频就跑命令，有图就看图，**不许凭空推测素材长什么样**。

```bash
ffmpeg -hide_banner -i "<video>" 2>&1 | grep -E "Duration|Stream"
ffmpeg -hide_banner -loglevel error -i "<video>" -vf "fps=1,scale=480:-1" "<out>/f_%02d.jpg"
ffmpeg -hide_banner -loglevel error -i "<out>/f_%02d.jpg" -vf "tile=5x4" -frames:v 1 "<out>/sheet.jpg"
ffmpeg -hide_banner -i "<video>" -vf "select='gt(scene,0.08)',metadata=print:file=-" -an -f null - 2>/dev/null | grep pts_time
```

必查六项，写成表：

1. 时长 / 分辨率 / 画幅 / 帧率
2. **目标主体在画面里的像素尺寸**（裁切后按比例换算，不要估个大概）
3. 主体是否被画面边缘裁切、是否被遮挡、出现帧占比
4. 主体最清楚的时刻（秒）与该秒视角
5. **是否真有水印**——用户常要求「去水印」，而很多下载件根本没有
6. 镜头切换点（决定分段位置）

命令细节、裁切换算和判读口径见 `references/video-material-audit.md`。

### A1 能力边界判定（先判死刑，再谈措辞）

拿 A0 的数据对硬阈值。任一条越界，**必须先说「这条提示词改不动，得改做法」**，再给替代方案：

| 硬阈值 | 越界后果 |
|---|---|
| 视频参考 ≤ 15 秒 | 超时必须分段；硬塞会被截断，后半段全靠猜 |
| 图片 ≤ 9 张，同主体建议 3–5 张 | 越多越「取平均」，一致性反而下降 |
| 主体像素高 < 200px | 禁止要求纹理、文字、小五金、缝线——模型只能编 |
| 主体像素高 200–500px | 只允许要求大结构：轮廓、颜色、材质、大件位置 |
| 主体像素高 > 500px | 才可要求局部细节 |
| 目标特征在时间轴上的出现占比 < 20% | 全局提示词会被平均掉，模型倾向「保持原样」，必须切专项片段 |
| 与原片同结构特征 ≥ 3 处 | 必须改用「差异清单」，否则模型只改色 |

把这条算出来给用户看，例如「单只靴子在画面里只有 60×270 像素，拉链宽约 10 像素，这个尺寸下要求拉链齿逐帧准确在物理上不可能」。

### A2 提示词结构体检

逐条打勾，不通过的就是问题：

- [ ] **每个素材都有 `@图片N` / `@视频N` 绑定**并说明用途。只写「原视频」「鞋子参考图」= 没接上，这是最高频的致命错误
- [ ] 前 300 字内出现核心动作（换什么、换成什么）。核心意图埋在第五段之后等于没写
- [ ] 单条提示词 ≤ 800 字。超过 1200 字，后半段基本无效
- [ ] **否定句 ≤ 5 条**。数一遍「不 / 无 / 禁止 / 避免 / 不得」，超过 20 条的编辑类提示词会让模型倾向「保持原样什么都不改」——这本身就是「换不上去」的成因
- [ ] 没有自相矛盾的指令（一边「重点锁定细节」一边「未展示的细节不擅自添加」）
- [ ] 没有针对不存在对象的指令（原片无水印却写整节去水印；无人物特写却写「保留面部微表情」）
- [ ] 没有模型执行不了的帧级要求（「逐帧跟随」「不随帧变化」「纹路不漂移」）——删掉不损失任何信息
- [ ] 保留项写成「保留什么」，不是把原片复述一遍

### A3 同结构替换陷阱（最容易被忽略的一条）

当「原片里的东西」和「目标素材」结构相似（同款鞋型、同为长靴、都带拉链、都是厚底），模型会判定「已经对了」，只做整体改色。用户看到的现象是「颜色变了，鞋底/拉链/结构还是原样」。

**解法：把「替换清单」改写成「差异清单」。**

对每个关键部件写三件事：

```
原的 A（必须消失）→ 新的 B（必须长出来），外观后果是 C
```

例：

- 原鞋是反光漆皮、有一道很亮的镜面高光 → 新鞋是哑光绒面、只有柔光，没有高光带
- 原鞋足弓下是镂空的 → 新鞋足弓整块实心贴地，前掌厚约 3.5cm、后跟实心梯形粗跟约 5.5cm，整体更矮

三件都要有：**旧的要死、新的要生、看得见的差别**。只写「新的是 X」不够，模型会把 X 叠在原结构上。

差异按「观众一眼能不能看出」排序，最显眼的三条放最前面。

**衍生问题：某部件只在少数帧里显眼。** 例：鞋底只在 1 秒里朝向镜头，其余时间是一条贴着地面的深色边。模型优化的是全片一致性，保持原样在 95% 的帧里都「对」，它就不会改。写法再详细也没用。解法是切出一个该部件占主导的 4 秒片段，只对它下一条单任务指令。

### A4 修掉三类高频错误写法

1. **小尺寸下的文字要求**。「230(1.5) 字口清晰」在 200px 宽的区域里必崩成乱码，而人对文字异常敏感，糊掉的数字比没有数字突兀十倍。改成「平整，不生成任何文字」。
2. **会破坏整体比例的位移要求**。「鞋底变薄，脚踝整体下移」→ 模型会去压腿长或让脚陷进地板。改成「脚掌平贴地面，小腿长度与身体高度不变」。
3. **无效的整节指令**。见 A0 第 5 条。删掉，或压成一句兜底。

### A5 输出审核报告

固定结构，不要自由发挥：

1. **一句话结论**：能不能靠改提示词解决；不能的话卡在哪
2. **素材实测数据表**：A0 六项 + A1 阈值判定
3. **问题清单**：分 P0（不改一定失败）/ P1（大概率失败）/ P2（优化项），每条写「现象 → 根因 → 改法」，指出对应原文片段
4. **重写版提示词**：可直接复制的代码块，按 A3 的差异清单结构组织
5. **降级路线**：改到极限仍不行时换做法（分段、先图像后视频、换镜头或换素材）

## 流程 B：投放文案合规审核

面向抖音 / 千川 / 商品详情。逐条扫，命中即标出并给替换词：

**绝对化与极限词**：最、第一、顶级、极致、唯一、首家、国家级、世界级、销量冠军、全网最低、绝对、100%、永久、彻底、根治。
改法：换成相对表述（「更…」「相比…」）或体验表述（「上脚轻」「不磨脚」「显腿细」）。

**材质与成分**：真皮、头层牛皮、羊皮、猪皮等动物皮描述，无资质不得使用；改为「绒面」「磨砂」「合成材质」等客观表述。防水、防滑、透气等功效需有依据，不用「绝对不滑」。

**医疗与身体功效**：瘦、矫正、增高、治疗、抗菌、防臭——风险最高，一律要求改为外观或体验描述。

**诱导与承诺**：秒杀、最后一天、仅此一次、包退包换（无依据）、划线价对比（需有依据）。

**平台敏感**：站外引流（微信、私域、二维码）、指名对比竞品、虚假紧迫感。

输出：命中词表（原词 / 位置 / 风险等级 / 替换建议）+ 一版合规改写。判定不确定时标注「需人工确认」，不假装确定。

## 通用反模式

- 不复述用户已经写对的内容来凑篇幅
- 不给「建议更具体一些」这类无法执行的建议
- 不为显得有产出就把 3 个问题拆成 15 条
- 用户原逻辑成立时直接说「没问题」，不强行唱反调
- 结论涉及数字（时长、像素、字数、条数）必须来自实测或可复算，不凭印象

## 与 seedance-video-prompt 的分工

两个 skill 常被同时加载，职责必须分清，否则会互相稀释：

| 环节 | 归谁 |
|---|---|
| 素材实测、能力边界判定、结构体检、差异清单、问题分级 | **本 skill** |
| 重写版的输出排版、`@素材` 引用语法、镜号/时间轴格式 | seedance-video-prompt |

规则：

1. 审核结论一律以本 skill 的实测与阈值判断为准，seedance 只提供输出形式。
2. 重写版优先套 seedance 的「模板六：视频编辑/改剧情」——`基于@视频1进行编辑` + 【保留】【修改】结构；该 skill 不可用时改用 `references/rewrite-templates.md`。
3. 两者冲突时（例如 seedance 鼓励「写意图不写细节」，而本次是局部编辑且细节即成败），以本 skill 的 A3 差异清单为准，因为局部替换的本质是把「不可见的相似」变成「可见的差异」。
4. 不要为了「都调用一次」而重复输出同一份提示词。一个回合内只交付一版可复制的完整提示词。
