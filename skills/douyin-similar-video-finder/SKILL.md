# 抖音相似视频查找

把参考内容转成可复用的风格条件，在抖音找到新的相似作品，并交付分类链接清单。默认用中文说明，交付 Word 文档；**每条至少 1000 赞，每类 10 条，而且核心画面风格必须相似**。点赞和风格同时满足才能入选。用户后续明确指定其他门槛、数量、分类或格式时服从指定。

## 浏览器与范围

- 本技能遵循用户选择，只使用真实 **Ego / ego lite** 操作抖音。先读当前可用的 `ego-browser` skill，再运行其要求的版本匹配使用指南。Windows 路径与实操问题见 [Ego 工作流](references/ego-workflow.md)。
- Ego 不可用时先排查或报告阻碍；不得切换 Chrome、Playwright MCP 或另一个浏览器完成任务。
- 同一任务只用一个 TaskSpace。需要登录或用户处理验证时交还控制权，用户确认完成后再接管并检查页面。不要索要密码或验证码。
- 查找、浏览和记录链接不需要点赞、关注、评论、私信、下载或发布；不扩大为这些操作。

## 工作流程

### 1. 理解参考

从整段复制文案中提取真实 URL，去重后在 Ego 打开。记录实际跳转的作品 canonical URL、作者、标题与可访问状态。分享文案中的数字、口令和时间不是作品 ID。

用户只给参考图片时，直接查看图片并记录可见风格，参考项写图片说明、保留本地图片来源；URL 可空，不推断图片所属视频或作者。

查看每条参考的实际画面，再总结 2–4 个主导风格维度，例如主体/鞋款、全身或局部构图、场景光线、配色穿搭、动作与剪辑节奏。明确其中不可放宽的核心项，例如“长靴上脚局部镜头”“居家坐姿对镜”或“夜景双人同框舞蹈”。视频开头不足以判断时补看代表性的中段画面。描述采样到的内容，不声称看完未看完的视频。

相近参考可以合并分类；差异明显的参考分别处理。分类名称和筛选条件来自本次参考，不固定为女鞋或五类。无法打开的参考可保留在“原始参考/待核验”中，说明依据和缺口；只凭分享标题推测时不得写成已确认的画面特征。

默认每类找 10 条新作品。用户否定过的推荐应从旧清单提取 canonical ID 存入 `excludedIds`，本轮不再推荐；没有否定时不自动排除旧作品。优先交付可靠结果，找不足时继续拓展关键词/作者/相关推荐，最终仍不足则报告实际数量与缺口，不降低门槛或用弱相关内容凑数。

### 2. 寻找候选

结合参考页的相关推荐、同作者其他作品，以及“核心风格 + 主体 + 场景/拍法”的搜索词找候选。按需求适当扩展作者，保留真正相近的同作者作品。

搜索结果和相关推荐只用于发现候选。取得公开渲染卡片中的作品链接后打开单条作品核验；不要把搜索页面、作者主页或商品页当成视频链接。

### 3. 核验与去重

对每条最终推荐，打开实际作品页，核对作者、标题、canonical URL、当前作品点赞数，并查看至少一个有代表性的清晰视频画面。风格依赖动作、双人同框或剪辑时，补看能支持该判断的时段。搜索缩略图和相同话题不能独立证明风格相似。

- 从当前作品作者区域确认上传者，别把被 @ 的账号、评论者或第一个 `/user/` 链接当成作者。
- 核心风格项必须通过；至少记录两个实际画面匹配维度，并写清相似点和重要差异。仅同作者、同标签、同为“靴子”或宽泛色调相近不够。参考核心是长靴上脚时，不用玛丽珍、静物商品或普通全身穿搭替代；参考核心是坐姿对镜时，不用走廊走路替代。注明差异不能作为放行核心偏离的理由。
- 点赞从当前作品的点赞区域核验；不要把收藏、评论、转发或作者总获赞当成点赞。记录原显示值、换算整数、核验时间和证据位置。`1.2万` 换算 `12000`；`1000` 可通过，`999`、隐藏、含糊或无法确认门槛的一律不入选。搜索卡片数字可用于预筛，最终以单条作品页为准。不要点击点赞按钮。
- 按 canonical 视频 ID 去重；原始参考不能算作新增推荐，同一作品也不能在多类中重复计数。必要时以文字交叉引用。
- 不同 ID 若明显复用同一段素材，也只保留一条；同作者、同鞋款可以入选，但须能区分穿搭、场景、机位或实际展示动作，不能用换标题重发凑数量。
- 图片轮播、合集或不可播放作品不混入已核验视频清单。无法核验画面的内容放在单独待核验备注中，不计入推荐数量。
- 仅提取公开作品标题、作者、卡片和画面。避免全量导出隐藏 DOM、聊天区、cookie 或登录信息。

在工作目录保存 `selection.json` 与必要截图证据，区分参考和候选；记录查看时间、画面观察与核验状态，方便复查。字段与导出要求见 [数据格式](references/selection-schema.md)。

### 4. 导出和交付

将通过核验的结果写入 `selection.json`。每类包含风格说明、原始参考以及新增推荐；每条推荐含作者、标题、具体相似点/差异、点赞原值与核验时间和完整可点击链接。顶层设置本次 `minLikes`、`targetPerCategory` 与 `excludedIds`，不可沿用旧文件中的虚构/未核验点赞。

使用本技能的导出脚本，避免重复拼装 Word 超链接：

```text
python <skill目录>/scripts/export_document.py --input <selection.json绝对路径> --output <清单.docx绝对路径> --markdown <清单.md绝对路径>
```

先可用 `--input <路径> --validate-only` 检查数据。脚本会拒绝低赞、缺少点赞证据、重复或已排除视频，并报告每类实际数量；数量不足仍可导出，但须明确缺口。运行所选 Python 前确认已具备 `python-docx`；依赖与校验范围见数据格式说明。日期取本次实际整理日期，不沿用旧任务。

生成 Word 时读当前可用的 `documents` skill，遵循其排版与渲染检查要求；逐页查看渲染结果，确认中文、长标题和链接没有截断。核对总数、分类数、参考与新增的区别，以及超链接目标。

完成浏览器任务时按当前 Ego 指南调用 `finish` 一次；只保留用户需要的页面。最终提供本地文档链接、实际新推荐数量与分类概览；有未核验项或数量不足时简明说明。无需向用户展示中间截图和 QA 文件，除非其提出要求。
