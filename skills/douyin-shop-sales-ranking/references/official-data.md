# Official public data notes

Read this file only when collecting Douyin public shop, live-room, or product data.

## Known identifiers

One shop can expose several IDs. Store each with a type label instead of treating them as interchangeable:

- Public/hash shop ID used by shop H5 pages
- Numeric report shop ID
- Numeric commerce/internal shop ID
- Creator `author_id` and `sec_user_id`
- Live `room_id`
- Product `product_id` and sale-channel `promotion_id`

## Public shop information

The following endpoint can return public shop identity for a hash ID:

```text
GET https://ec.snssdk.com/shop/getInfo?id={shop_hash}&b_type_new=0&device_id=0&is_outside=1
```

Useful fields can include `id`, `report_id__for_event`, and `shop_name`.

Legacy shop catalog endpoints may return transient error `100111`. Do not retry indefinitely or assume an empty response means no products.

## Live-room product list

When the creator is live, open the yellow cart and observe:

```text
POST https://live.douyin.com/live/promotions/page/
```

Important query fields:

- `room_id`
- `author_id`
- `offset`
- `limit`

The response can contain `total` and `promotions`. Useful product fields include `title`, `cover`, `detail_cover`, `product_id`, `promotion_id`, `detail_url`, `shop_id`, `in_stock`, and `can_sold`.

This is the current live-cart scope, not the full shop catalog. Prices can be `-1` in the list response.

## Live product price enrichment

The page can request:

```text
GET https://live.douyin.com/live/promotions/page/get/
```

Useful parameters include `room_id`, `author_id`, `product_infos` as a JSON array of product IDs, and `request_scene`. It can accept multiple product IDs in one request. `min_price` is commonly in cents; confirm against the visible page before dividing by 100.

The endpoint can also return live selling points such as viewers, favorites, visitors, or cart additions. None of these are sales.

The current explained product can appear at:

```text
GET https://live.douyin.com/live/promotions/pop/v3/
```

## Product detail limitations

Product pages or BFF endpoints may return risk-control pages, empty bodies, or QR-only views. Preserve the browser session and use requests naturally generated by the page. Do not reuse stale signatures or fabricate missing data.

Public product pages commonly expose current price and cumulative sales but not a historical 7-day series. A cumulative value belongs only to the exact product/promotion ID that returned it. Do not copy it to a same-title relisting.

## Data quality labels

Use one of these labels per sales value:

- `exact_7d`: exact seven-day unit sales from an authorized or explicitly dated source
- `estimated_7d`: platform-estimated seven-day unit sales
- `interval_7d`: seven-day range rather than a point value
- `snapshot_delta`: difference between two documented cumulative snapshots
- `cumulative_only`: cumulative sales with no historical comparison
- `unavailable`: no valid sales value returned

Only `exact_7d`, `estimated_7d`, or valid `snapshot_delta` point values can be numerically ranked. Keep `interval_7d` separate unless the user explicitly requests interval sorting.
