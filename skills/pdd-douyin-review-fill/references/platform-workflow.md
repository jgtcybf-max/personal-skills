# 当前后台读取路径

页面布局、权限和导出格式可能变化。以下为已成功执行过的路径；每次运行先确认当前可见标签、店铺和字段，再选择定位器，不把示例网址当成固定入口。

## 拼多多

- 商家后台 → 商品管理 → 商品列表，历史入口 `https://mms.pinduoduo.com/goods/goods_list`。
- 在“商品ID”筛选框查询用户给出的 ID。已验证该输入框可以空格分隔多个 ID；仍以当前页面提示为准，检查结果覆盖全部 ID，注意分页与状态筛选，不把“在售”之外误认为不存在。
- 每一商品读取商品 ID、商品编码／货号、标题和图，记录结果所在行，避免把相邻商品的“修改库存”点错。
- 点击该商品行的“修改库存”。弹窗曾显示每条规格的“规格 ID: …”和“规格编码: …”，另有颜色、尺码及库存。确认弹窗商品 ID 与本次查询相同。
- 若当前模板只要求一组 SKU，选一个可以在抖音找到完整对应规格的 SKU；已有示例则优先保持同一组。可优先从首个可见 SKU 查起，但其排名本身不是匹配依据。
- 规格表可能虚拟滚动；只渲染前 10 条不能推出总共只有 10 条。不需要所有 SKU 时读取已确认的那条即可；逐 SKU 任务则需要完整滚动采集并核对数量。
- 采集商品 ID、SKU ID、规格编码、所有显示的规格值及原始弹窗行文本。点击“取消”并等待弹窗关闭，不按提交／确定。

先查现有会话，管理员桌面客户端无法操作时切到 Ego 登录。扫码仅由用户在官方页面完成，二维码不要存进 skill，不能从其他浏览器提取 cookie 绕过登录。

## 抖店

- 商品 → 商品管理，历史入口 `https://fxg.jinritemai.com/ffa/g/list`。可在售商品列表通过“导出”生成当前商品及 SKU 明细，完成后在导出记录点“下载报表”取得文件；记录导出时间、店铺、筛选状态。
- 一件商品常在导出中对应多条 SKU 行。先读取实际列名，确认商品 ID、规格编码、SKU ID、规格、链接和商家货号的含义，不按位置盲解。
- 一次已验证导出布局：A 商品 ID，B 标题，J 规格编码，K SKU ID，L 规格文本，T 商品链接，U 商家货号。此映射只是线索，不是未来文件的固定契约。
- 若目标不存在于当前导出，检查筛选、上下架状态、导出范围与店铺。不要因为相似名称存在就替代它。
- 无可用导出时，按货号查询商品，复制后台“商品链接”；打开“编辑价格”等可见 SKU 明细的弹窗读取 SKUID、颜色和尺码，查看后取消。
- 链接曾使用 `https://haohuo.jinritemai.com/ecommerce/trade/detail/index.html?id=<商品ID>&origin_type=604`。保留后台实际链接，解析其中的商品 ID 与对应记录核对，不仅凭模板拼接网址。

## 原始证据与恢复

在本轮工作目录按商品 ID 保存原始 DOM 文本／导出行与标准化结果，避免在长批次中重复查询。数据要绑定商品 ID，不能按页面首行或数组下标无条件合并。

浏览器会话结束、页 ID 失效或登录过期时重新发现当前状态，复用已核实的本轮证据继续未完成项。历史 JSON 可以提供线索；新批次仍需核实当前资料，不拿旧 ID 和旧链接当本次数据。
