# 超级编导画布素材上传

通过用户已打开、已登录的超级编导完成素材上传。默认画布为 **小蒋无限画布**，用户指定其他画布时使用其指定名称。“无线画布”通常指界面中的“无限画布”，按实际名称核对。

用户只要求排查、优化skill或整理流程时，仅做相应诊断与本地验证；不把它当作上传、下载或付费任务续跑。出现“继续”先按当前活动事项理解，不自动恢复旧生成任务。

## 默认快速路径

- **接未完成批次**：先读现有清单和本次独立任务组的上传证据，同组已核节点不重传；用 [upload_queue.py](scripts/upload_queue.py) 生成缺项批次，状态不明先核原节点。只需上传时不解码视频、抽帧或调用视频分析。
- **一个工作区域完成**：确认目标画布和空白区域一次，保持侧栏/缩放稳定；视频和图片分批放在同一输入列，不每批回首页、适应全画布或重找整组。
- **文件框一次填入并回读**：优先 [upload-dialog.mjs](scripts/upload-dialog.mjs) 将整批绝对路径写入已观察的原生文件名Edit并验证，省掉切目录及反复粘贴。它不按“打开”，不声明上传成功；核回读后单独确认打开。
- **一次调用完成稳定动作**：已观察的非付费字段操作顺序执行，末尾集中返回回读和必要截图；未知菜单/弹窗、焦点变化先观察，不每个按键一轮对话。
- **每批集中核验**：一次读取本批全部文件名/缩略图和保存状态，节点列表可用于名称核对；不逐图打开预览。缺名、缩略图异常或内容疑点才局部放大。最后只做一次整组布局/完整性总览。

工具调用和续跑命令见 [快速上传](references/fast-upload.md)。所有上传仍走真实桌面文件框，不使用未核实接口，不为提速清空旧节点或默认增大批次。

## 准备素材

- 从当前请求取文件或目录；路径指向目录时检查其内容，不把目录名当成缺少扩展名的视频。可以按用户提供的作品 ID 精确定位子目录中的 MP4。
- 先列清单，保留原文件及原名。用户说“全部图片”时包括 logo、鞋底、内里等辅助图，上传阶段不擅自筛掉。视频目录中另有 MP3 不等于用户要求单独上传音频。
- 首次可用 [scripts/materials.py](scripts/materials.py) 生成 UTF-8 清单及多选文本；已有清单直接复用，不另扫描。目录默认只取当前层的图片和视频；只有确实需要查子目录时加 `--recursive`。
- 完整视频替换任务若已使用 [prepare_run.py](../superdirector-canvas-video-replace/scripts/prepare_run.py) 生成本次 `upload-manifest.json`，直接复用并只补缺失，不再运行一遍清单脚本。单纯上传任务仍用本技能，勿为上传而解码整片。
- 脚本按扩展名整理素材，不代表应用接受所有列出的格式；已实测 MP4、JPG、PNG，其余以实际文件选择框和上传结果为准。

```powershell
python -X utf8 "<skill>/scripts/materials.py" --video "<原视频或其目录>" --images "<图片目录>" --manifest "<任务目录>/upload-manifest.json"
```

`<skill>` 是本 SKILL.md 所在目录。命令按素材类型与父目录分组，默认每批最多 5 个文件；这是根据本机漏传现象采用的保守策略，**不是应用已证实的硬上限**。每批保留绝对路径 `selection_file`，另提供 `directory` 和仅含带引号文件名的 `short_selection_file`。已进入并确认该目录时用短名称选择，减少长路径输入；未确认目录时用绝对路径。多视频目录不明确时，只上传已指定的视频，不能挑一个猜。

## 进入画布并上传

按 [references/canvas-layout.md](references/canvas-layout.md) 的用户示例预留区域：商品图左侧竖排、原视频左下、右侧中间留给生成/结果，同一任务一个编组。单纯上传只整理输入并预留右侧，不创建生成任务。张数按实际清单，不固定为示例5张。

1. 用 Windows MCP `Snapshot` 查看当前桌面，再切到现有超级编导窗口。核对左侧所选画布和顶部标题都为目标画布。不要新建同名画布、清空画布或覆盖已有节点。
2. 每条新来源先选新的空白区域建立独立任务组，使用新区素材副本/重新上传原图及全新生成节点；不复用旧成功分组素材或向其增删连线。原成功分组的引用、提示词、参数、连线、位置、名称和结果均保护。仅续跑同一新任务组时比对其节点和清单，补缺失项；不能按全画布文件名去重。已验证入口：**空白处右键 → 上传 → 本地上传**。菜单位置随鼠标变化，每次以实际截图定位；底部上传入口也可在核实后使用。
3. 观察真正的原生“打开”框后，在文件名Edit一次写入本批带引号的**绝对Windows反斜杠路径**，无需切目录。已有原生Edit句柄时复用至该弹窗关闭；新弹窗重新观察句柄/PID。[upload-dialog.mjs](scripts/upload-dialog.mjs)封装批次与`nativeText`全文回读，超长选择由队列拆批；不把正斜杠路径直接粘进Windows文件框。原生Edit不可用时，在已观察字段单击→全选→粘贴本批绝对路径→复制回读，一次调用完成；不要反复切换两种通道。先视频再图片，每批核实后下一批。
4. 弹窗可能延迟出现。观察到真正的文件选择框再输入，粘贴后核对文本已在文件名栏再点“打开”。单个工具返回成功不代表点击生效，也不代表上传完成。
5. 不跳转首页的生成输入区，不建立换鞋任务，不点击“生成”“发布”。如果用户正带着逐步演示，上传核验完成就停在本步。

## 核验与补传

- 集中比对本批每个文件名和缩略图，节点列表名称可读时不为读名称反复缩放；一次局部截图足够时不全屏截图。不能只凭工具成功、总数或缩略图总面积下结论。名称相同的不同目录仍要核商品/节点身份，不能全局按basename去重。
- 一次提交 9 张却只出现前 5 张在本机发生过；缺图原因未确认。只对清单中**确实缺失**的文件补传，不整批重传、不把这次现象当成固定上传限制。
- 有重叠或遮挡时，先查看/调整本次节点以确认，不删除未知节点。只有本次上传的节点可以为布局而移动。不要盲目拖动空白处：不同选择/平移模式下可能框选或移动视野。
- 等待缩略图完成、无上传错误，并检查顶部“已保存云端”等状态。如果只能确认画布出现，未确认远端素材可用，则如实报告证据范围，不声称完成远端持久化验证。
- 本批UI证据确认后记为`verified`；上传点击超时、未看全或保存未知记`unknown`并先查原批。队列不把字段回读、文件存在、输入工具ok当上传完成。输入素材不变时复用已核证据，最后统一检查云端保存；网络上传等待不固定睡满30秒，30秒只是无进展时的排查点。
- 上传无进展约 30 秒或出现明确失败时，先检查实际 UI；单文件最多自动补传一次。重复失败或状态不确定时停止该文件，报告已完成/缺失清单，避免重复节点。不要为此重启正在演示的应用。

## 点击无效、权限或坐标不匹配

普通 Windows MCP 优先。一次可验证操作无效后，核对焦点、桌面和输入是否被拦截；不要连续盲点。管理员超级编导拦截普通权限输入是本机已遇到的原因，不能把所有无响应都归因于此。

只有需要输入管理员应用时，读 [references/desktop-input.md](references/desktop-input.md)，使用 [scripts/desktop-input.ps1](scripts/desktop-input.ps1) 的临时助手及 [desktop-client.mjs](scripts/desktop-client.mjs)常驻客户端；本批复用通道，不每次输入新启PowerShell。助手显式使用物理像素和UTF-8，到期不自动续开，结束停止。系统UAC由用户处理；不改UAC、自启动或权限。不固定历史PID/窗口句柄/调试端口，不为上传重启应用开启调试。

## 交付

简短报告：目标画布、视频与图片实际完成数量、是否已看到云端保存、缺失项（如有）。保留原文件、应用和画布当前状态。如果用户在教学，结束语是“本步上传完成，可以继续下一步”，不自行推进生成。脚本验证及本次已验证实例见 [references/verified-workflow.md](references/verified-workflow.md)。

用户后续明确要求根据视频和商品图写提示词并生成时，转用 [superdirector-canvas-video-replace](../superdirector-canvas-video-replace/SKILL.md)：在本次新区独立任务组连线，先480原生测试审核，通过后另建1080节点保留480，下载后本地加原音核验；旧成功组保持原样。本上传技能自身仍止于上传。
