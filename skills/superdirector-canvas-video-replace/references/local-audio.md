# 本地加回原视频配音

用户明确：1080视频下载成功后加原视频配音，超级编导内加不进去，不需要再尝试。音轨处理只在本地做；这项规则不是关于其他平台能力的泛化结论。

## 确认输入和同步

- 默认正式交付输入是用户原视频和已下载的1080正式版。当前任务已授权480测试或诊断原音预览时，也可处理对应下载版，名称与说明明确标480/诊断，不能当成1080正式交付。按归档记录定位原片，不能拿“最终原声版”再次作为原配音来源。
- 检查原片的音频流数量、语言/内容、首个音视频时间戳、时长，及1080视频流时长。单音轨默认保留整轨；配音、音乐和环境声已混合时不做声音分离。素材包已提取对应MP3时优先使用该确切文件；删段生成参考须用同剪点配套音频。原片无音轨时检查是否有明确对应的已提取音频并核对同步；没有有效来源就说明，不能配假声音或把静音当完成。
- 将开头、主要切镜/动作、结尾等时间锚点对应起来。输出时长或帧率与原片不同不一定只差结尾；可能全片速度或局部剪辑已变。不能只比较总秒数就判断同步。
- 声画时序相同可直接封装。仅固定起点偏移可校正偏移；局部漂移需依据镜头锚点对齐并复核。不要默认变速配音、拉长画面、冻结末帧或循环音轨。必须调整时保留正常语速和完整句子，记录实际处理及影响；无法可靠对齐则标明未完成同步，不能交付为通过。

## 封装原则

FFmpeg优先传入参数数组，路径包含中文、空格、#时不要拼接到未转义的shell字符串。输出使用新文件、`-n`防覆盖。

仅在声画时间线已核对一致、且原音频编码可封装进MP4时，命令结构为：

```text
ffmpeg -n -i <1080下载版> -i <原视频> -map 0:v:0 -map 1:a:0 -c:v copy -c:a copy -movflags +faststart <1080最终原声版.mp4>
```

- 显式映射生成画面和原视频音轨，去掉生成音轨，不能叠加出双声。
- 不预设MP3必须转AAC。目标容器与使用场景支持时，优先实际验证音视频流复制：核输入/输出压缩流哈希、单音轨、完整解码、首PTS及编码延迟/尾部填充。MP3在MP4中封装成功不保证目标播放器兼容；未实播就写待核，可保留AAC备选。
- 原音频不能可靠封装或目标播放器需要AAC时只转音频，视频仍流复制；这属于音频转码，不应声称音轨逐字节未变。转码后核重建峰值，不能仅凭浮点峰超限断言可闻爆音；未听审不得写声音通过，也不自动增益、限幅或裁尾。
- 上例不是时长不一致时的自动对齐命令。**不要默认加 `-shortest` 或 `-t`** 截掉原配音尾句，也不能让完整音轨拖出无画面的长尾。
- 不因输入帧率与原片不同就重新编码1080画面。确有时间对齐需要修改画面时，应采用尽量少的修改并重新检查商品和动作。

## 最终检查与备注

检查全片可解码，实际画面尺寸与1080下载版一致，音轨来自原片且无重复；听开头、中段、结尾，查看配音是否错位、句尾是否被切、是否爆音或意外静音。默认保持原音量，不自动加增益或降噪。

同目录保存新文件，名称包含货号、批次、1080和“最终原声版”；不覆盖原视频和1080下载版。将以下信息追加到该版说明中：

```markdown
对应480测试片：…（通过）
对应1080下载版：…
音轨来源：原视频路径、所选音轨
处理：替换生成音轨；音频流复制/转码；时间偏移或其他对齐（无则写无）
最终参数：实际尺寸、帧率、音视频时长
画面检查：…
原配音检查：首段/中段/尾段同步、音量、尾句完整性、是否有双声
最终结论：通过 / 有瑕疵 / 不通过 / 未完成同步
```

本参考仅规定后续执行方法；创建或修改skill不触发真实视频处理。
