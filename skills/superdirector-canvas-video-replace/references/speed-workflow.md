# 画布任务的默认快速执行

先减少工具往返和返工，平台渲染速度单列。只要求优化流程时只改本地技能/工具，不启动旧任务或付费测试。完整两阶段仍为480通过后1080，再本地配原音；最新用户政策决定能否提交。

## 工具往返最少化（2026-11-16）

定位本身不预设为瓶颈。分别计输入发送、观察截图、模型往返、界面异步等待和平台渲染；缺少完整日志时不能凭聊天长度断言哪项占比最大。

- 已经需要临时输入助手时，用上传技能的 `scripts/desktop-client.mjs` 在持久Node会话直接通信；助手只启动一次，不为每个click/keys/text再启动PowerShell。通道到期不自动续开；任务结束停止。普通桌面工具已有效时继续用它，不额外提权安装。
- 稳定界面下，把同一语义操作放进一次工具调用，例如“已观察的输入框单击→全选→粘贴→全文回读”，最多6个已知非付费动作，逐项await。打开未知菜单/弹窗、窗口焦点改变或需要新坐标时立即停下观察，不盲批。
- 连线首条验证后，已观察且不随选择改变的端口可连续两条再集中核对；不能为提速跳过最终每张图和视频身份/顺序。参考图预览的“下一张”入口和编号规则已观察且稳定时，可在一次工具调用内顺序采集六张编号截图，返回带序号拼图或全部图供一次判断，不逐张六轮对话。节点搜索只定位一次，记录ID，坐标只在当前视野有效。
- 用助手 `screenshot` 一次捕获并缩图：全屏用于定位/焦点，固定面板用物理区域截图。返回原点和缩放系数，点击统一换算；无需再启动截图CLI和Python缩图。截图只看真实桌面，遮挡仍须处理。
- 提示词用 `clipboardRead` 返回UTF-8全文，与定稿比较，不再单独启动PowerShell读剪贴板。只在刚执行本任务复制后读取，不读取无关剪贴板内容。
- 不对每个动作固定睡1秒。需要异步UI时按实际状态观察；初次变化用短等待并核结果，未就绪继续等，不因工具ok默认成功。长渲染维持原来的20—40秒检查节奏。
- 付费动作始终单独调用：关闭菜单→独立观察底栏→单次生成→独立核受理。不能放进sequence；超时或回执不明先观察并查原任务，禁止自动重发。

客户端有串行队列、请求ID匹配、到期检查和超时停发；`ok`只代表输入动作，不代表画布已完成。输入可带当前 `expectedForegroundHandle`，焦点不符先拒绝发送。读取状态/截图不能证明商品或质量通过。调用见 [输入助手说明](../../superdirector-canvas-upload/references/desktop-input.md)。

## 续跑从缺口进入

运行 scripts/resume_card.py --record <执行包/task-record.json> --out <执行包/续跑>；本用户排除目录用 --exclude-dir "C:/Users/TTT/Desktop/小蒋灰底图/不用查看" 传入。

读最新用户指令和续跑卡.md，只展开resume.json指向的缺项或矛盾。卡片带主记录SHA256，只读确切路径，不扫描素材盘，也不证明UI状态或授予生成权限。已下载结果先做本地，不为查旧任务激活桌面/启动助手。缺卡片可直接读主记录，不重建完整聊天。

素材/参数不变时复用签名有效准备与审核；真实新1080仍独立审核。交接只带主记录和哈希、当前节点/任务ID、确切下载、下一步和必要输入通道到期时间；不能把已受理交接成待生成。

## 准备一次，UI只改差量

首次运行 prepare_run.py --video <确切源片> --images <商品图目录> --out <任务/准备01>，已知风险动作加 --focus 起点:终点:步长，续跑签名一致加 --reuse。它输出清单、上传选择文件、原片和商品总览、首两尾帧、参数、操作卡及两段提示词模板。先分析材质与动作，再写生成稿，编号以实际UI图序定稿；工具不判断商品或授权。

| 工作 | 每条保留的确认 | 省掉的重复工作 |
| --- | --- | --- |
| 上传 | 批次文件名/实际节点/云端保存 | 新来源新区独立素材副本；同组续跑才只补缺失 |
| 连线 | 第一条验证，稳定后两条一组，最终逐项核引用 | 不每条全屏截图，同组不重连正确继承的线；旧成功组不增删连线 |
| 提示词 | 当前节点完整回读一次，与定稿核对 | 不反复改写或截首中尾猜已填入 |
| 参数提交 | 关菜单后独立截图读底栏和点数，随后单独生成 | 不合并配置和付费点击为盲动作 |
| 转1080 | 480通过/政策允许，新节点ID/引用/全文/1080/1条/点数 | 只改阶段参数，不重上传分析排版 |
| 受理终态 | 新生成状态/任务身份/确切下载 | 副本旧完成缩略图不算新受理，未知不补点 |

新来源在新空白区按用户布局预留商品左列/源片左下/结果右侧独立任务组，旧成功组完全保护；上传即放目标区域，只做必要对齐。窗口/缩放变化重观察，不复用旧坐标/PID。固定布局用局部图，定位或布局变化才看全屏。一次无付费可见验证成功后本批复用输入通道，失效才排查，不每色测试多个工具。助手核到期、结束停止，不无限续期或改UAC。

## 同批任务交错推进

唯一桌面操作者：A单次提交并核受理 → 配置/提交同批已授权且独立的B → 完成节点优先下载。A的480通过且政策允许即可做A的1080，不等全批480。用户只许一条、亲审或有全批依赖时遵从门槛。交错处理不增加数量/重试，不多代理抢桌面。

正常生成等待按变化20—40秒检查，慢时可延至60秒以内；接近完成或状态变化才更快复查，不每几秒截图静止画面。等待时准备下一款或处理下载。单次等待不超过60秒。没有画布官方MCP/API可用证据时沿用已验证通道，不为找插件/调试端口中断已登录流程。

## 下载即送本地队列

UI确认确切文件下载完成、无临时扩展名且大小稳定后写该条小清单，运行 [finish_downloads.py](../scripts/finish_downloads.py)，桌面继续下一项，本地最多两个工作并行；两条都已到齐可同清单并行。一条失败不堵住其他就绪任务，不等全批齐了再手写脚本。每个新到文件/就绪小批用独立输出目录；已签名清单不追加新项去覆盖旧会话，--reuse只用于原清单恢复。

清单外层jobs，每项唯一key（1—64个英数字/下划线/短横线）、product、video、original_audio，另可带source_video和focus（如["0:3:0.2"]，按本片动作定）；均用绝对路径：

```json
{
  "jobs": [{
    "key": "shoe-black-1080-nodeid",
    "product": "货号-颜色",
    "video": "C:/本次确切下载.mp4",
    "original_audio": "C:/本剪辑配套原音.mp3",
    "source_video": "C:/实际生成参考_静音.mp4"
  }]
}
```

```powershell
python -X utf8 "<skill>/scripts/finish_downloads.py" --manifest "<任务>/本地处理.json" --out "<任务>/本地处理01" --jobs 2
# 中断后同清单、输入和参数续跑：
python -X utf8 "<skill>/scripts/finish_downloads.py" --manifest "<任务>/本地处理.json" --out "<任务>/本地处理01" --jobs 2 --reuse
```

入口准备参数/总览/首两尾帧/指定重点段、配原音核看片、流复制/唯一音轨/全解码证据。source_video仅记录关系，不以总时长自动判同步。商品语义、关键动作、首中尾同步听审和目标播放器兼容仍单独确认；技术成功不自动放正式通过目录。仅需画面时用review_media.py，不对同片连续运行两套完整准备。--reuse核输入/工具/参数/产物签名，完整产物不重解码合音，签名变化拒绝覆盖。具体缓存和部分失败行为以工具 --help 为准。

不把写死旧货号/目录的临时脚本改几行用于连续生产。原音与剪点不对应先定位配套音频；不得默认shortest、裁尾、变速、循环、冻结、拉伸或调整音量。容器不兼容按local-audio.md处理，优先保留视频位流。

## 一条一次审核，一次合并

- 每条一名审核者，输出输入SHA256、通过/有瑕疵/不通过、范围、问题秒数、证据路径；画面/技术原音/实际听审分别记录。颜色间并行，不多代理重复抽同片全部帧。
- 先看商品多角/成片总览和关键动作，疑点才补连续帧/局部，先对照源片排误报。未实时听看如实标未审，不能用长报告代替。
- 主代理核审核输入身份、结论与交付哈希即可；矛盾/高风险才第二人复核。子代理没执行、无产物或答旧任务，检查现有产物后直接重派缺项，不反复唤醒失效代理。
- 提交受理后立即记ID/参数/点数；下载及审核完成各合并一次。状态不变不改账本，不重复渲染全套报表。记录单写入者，费用/进度/交付由它派生。
- 本用户当前布局：原视频/要看的视频（480）/1080视频/其他资料。视频目录只放视频，说明费用证据和历史集中其他资料。相同哈希不复制整片，旧说明集中保存，不多建最新入口。其他任务指定目录从其约定。

## 实测与速度承诺

阶段转换时把workflow_clock.py与正常调用合在一起，别每次鼠标操作另记：

```powershell
python -X utf8 "<skill>/scripts/workflow_clock.py" --log "<任务>/流程计时.jsonl" start prepare
python -X utf8 "<skill>/scripts/workflow_clock.py" --log "<任务>/流程计时.jsonl" next upload
```

操作阶段prepare/upload/connect/configure/review/audio/archive，等待platform_wait/download_wait；480/1080可重复，用--note区分。中断停当前段并记原因；并行工作另记起止/重叠，不把单线日志当全部代理总耗时。缺失阶段未知，不记0。

用report --baseline-log <同范围完整日志>比较；素材数量、阶段次数、审核范围一致且日志完整才能谈整套提速。50%是目标，本地缓存几秒实测只证明该步骤；平台等待不能由本地工具保证缩短。无完整旧计时不补造已快50%。
