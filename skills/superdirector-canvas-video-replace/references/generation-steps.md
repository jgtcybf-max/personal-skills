# 画布配置、两阶段生成与引用核对

## 输入与素材分析

- 路径指向目录时，先列清单定位实际视频；同目录MP3不作为原视频。多个候选且无法按用户提供的标题/作品ID区分时再问。
- 同目录以后会有已归档的测试片。结合 `__测试…` / `__首版…` / `__正式…` 文件名及 `__记录.json` 中的 `source_video` 识别真正原片，不能把上次成片当新原视频，也不能将目录内所有MP4全部上传。
- 新来源用 [画布上传技能](../../superdirector-canvas-upload/SKILL.md)在新空白区域建独立素材副本；只有同一新任务组断点才复用其节点、只补缺失。旧成功组的素材、引用、参数、连线、位置、名称和结果原样保护。
- 记录原视频文件、商品图目录、视频时长/尺寸/帧率/音轨，以及动作和切镜顺序。看实际商品图，区分整体角度与logo、鞋底、内里等细节图。
- 每次写视频提示词前，先记录目标商品的材质依据：用户或商品资料明确的成分、图片可见的表面质感，以及尚不确定的部分。不要沿用上次货号的材质描述；具体写法见 [提示词原则](prompt-principles.md)。
- 提示词分两步：先用[素材分析提示词](../assets/material-analysis-prompt.txt)看本次真实视频和商品图，输出`01_素材分析.md`；再用[生成提示词模板](../assets/video-generation-prompt-template.txt)依据分析写草稿。实际引用列表核对后才填最终编号、删除占位并保存定稿，分析指令本身不进入生成框。
- 连接能覆盖目标外观的多角度图，实际数量由模型限制与画面需要决定。上传全部图片不等于每次生成必须连接全部图；记录本次连接了哪些图和顺序，不能把细节图当成整体鞋型。
- 原物体和目标商品形状有差异时，需要允许重建完整物体轮廓，而非只改颜色。不能同时要求保留旧鞋轮廓又要求换成不同鞋头、鞋底或鞋跟。


## 画布连接与测试生成

- 默认采用用户指定的 [画布排版](../../superdirector-canvas-upload/references/canvas-layout.md)：商品图左侧竖排，原视频置左列最下，生成/结果在右侧居中，连线从左向右汇入，同一任务一个编组。先定位和排版再连线，新来源在新空白区建立独立任务组、新素材副本和生成节点；旧成功组原样保留。仅同组续跑复用，480和1080各用独立新节点。
- 先用 Windows MCP Snapshot 观察实际界面，再恢复现有超级编导窗口，核对左侧选中项和顶部画布标题。不要清空或重建同名画布。无响应时是否恢复/重开按当前用户授权；先保留保存状态、节点及在途任务，重开后重新核焦点和任务，不改权限或UAC。
- 原视频节点右侧连接口可通过“引用该节点生成 → 视频”建立视频生成节点；已有本任务节点则续用。选择支持原视频编辑及图片参考的模式，检查模型是否支持所需输入。不要把普通文生视频误当原视频编辑。
- 在最早可进入的配置面板先核实本次时长、480原生和数量1；需要原视频才能显示支持范围时，先引用原视频做未提交草稿，再判断，避免全部商品图连完才发现不支持。当前资料只能提供检查方向，不能代替真实选项。1080支持范围能提前查看时一并记录；当时不能确定则标未核实，不推迟已授权的480来猜入口。
- 商品图节点选中后，从其右侧连接口拖到目标生成节点的左侧输入口。先验证第一条线；当前端口位置已观察且连线后布局稳定时，可顺序完成2条再集中核对，不为每条线都单独往返截图。端口因选择而变化、遮挡、平移、缩放或异常时，立即回到单条确认。最终打开生成面板逐项核对原视频、每张参考图及顺序；缩略图堆叠时点开查看列表。**画面上有线还不足以证明模型引用成功。** 已验证操作及输入问题见 [canvas-workflow.md](canvas-workflow.md)。
- 填入提示词前核当前前台窗口、焦点及目标字段；切换Codex/其他窗口后重新核。先一次无付费的可见输入验证，粘贴后回看实际全文或首中尾与图号，不能以工具ok或本地定稿代替UI确认。避免误写重命名框或聊天草稿；提示词中“参考图1…N/参考视频1”的编号以最终面板为准。保存实际提交的完整文本。
- 打开参数设置，明确选择 **480原生、1个**，比例随原片，时长按原视频或自动识别。模型沿用用户指定或当前支持的模式，不能因历史示例而固定某个模型。找不到480原生时核查当前模式/可用模型；无法满足则说明缺少的选项，不擅自升级720P、1080P或消耗更多点数。
- 提交前一次性核对参考列表、提示词、视频编辑模式、实际模型、480原生、比例、时长、数量和预计点数。先关闭参数菜单，再用截图复核底栏实际参数和预计点数，确认后单独点击生成，避免关菜单时改选清晰度。用户已要求本次生成则直接提交一次，不重复索要确认。用户只要求建skill或写提示词时，不创建付费测试任务。
- 提交后记录受理并持续跟进至终态。**同批多个已授权且互不依赖的款色，不要求守在A节点等完才配置B**；可在A生成中配置/单次提交B，已完成结果优先下载并送本地审核。用户只授权一条、亲自审核或有跨款依赖时按该门槛等待。不因进度停留或发送超时再点生成；明确失败保留记录，状态未知先查原任务，不重复付费。


## 480审核通过且任务政策允许后生成1080正式版

- 先读最新用户限制和`generation_policy`。质量通过与新阶段授权分开；本任务明确禁止已生成款色新增阶段时，保留480并转下载/审核/原音/归档，不提交1080或重试。
- 完整两阶段已获授权时，每款480通过即可推进其1080，不人为等待全批480全部通过；原任务受理身份和最新政策仍逐条核对。下载/审核与其他款色UI配置交错推进，桌面只有一个操作者。
- 先保存已通过的480成片、检查记录、实际提示词、参考顺序、模型和其他参数。480下因分辨率无法确定的小logo或纹理可列为1080待复核项；已明确看到的结构错误、标志变形或穿模不能当作单纯看不清而放行。
- 1080使用独立新节点，保留480节点、结果、参数和连线。专用高清入口只有确认会创建独立新结果且不改480时才可使用；否则在本次新任务组创建正式版新节点，接同一新组的原始视频和商品副本，沿用通过的完整提示词，选1080/1条。不能在480结果上直接换参数覆盖，也不能复用旧成功组的节点。复制仅在已确认独立且不会改源节点时使用，引用继承仍须核实。
- 复制后先核新节点ID、引用及完整提示词，只修改本阶段需要的参数；不重连已经正确继承的图、不重写已经通过的语义约束。副本继承的“已完成”缩略图不是新1080受理证据；独立单击后必须看到本次生成状态或真实新任务ID再记已受理。
- 1080仍应引用原始视频和商品图；不能默认把480成片当作唯一输入再编辑，造成再次换鞋或动作偏移。若使用基于已通过成片的专用高清功能，说明实际输入和处理方式。不得用本地简单拉伸冒充平台1080生成，也不能保证重新生成与480逐帧完全相同。
- 提交前核对1080选项、实际模型/模式、参考列表、提示词、时长、比例、数量和预计点数。按实际UI标签记录，“1080标准”不因没有“原生”二字就判为不支持；核实它是平台1080生成及真实输出，不能用本地放大冒充。当前模型没有1080时先检查支持范围；无法实现则保留已通过480并说明，不擅自换模型、改变外观或用720代替。
- 提交一次并跟进完成；下载后读取实际尺寸、帧率、时长和音轨，确认真实输出。命名与说明明确“正式01 / 1080 / 对应测试01”，正式节点也应有可识别的阶段名称。
- 再对照商品图、原片和已通过480版本检查核心鞋型、logo/纹理、动作遮挡及跨帧稳定性。**480通过不等于1080自动通过。** 正式版出现漂移或新错误则记录时间点和差异，标为有瑕疵或不通过；在当前授权内处理，不反复盲目付费。
