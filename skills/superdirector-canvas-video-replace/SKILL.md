# 超级编导画布视频元素替换

使用已登录的超级编导桌面端和用户指定画布，默认 **小蒋无限画布**。本技能执行连续视频元素替换。用户只要求写提示词、维护流程、排版规范或优化skill时，只处理相应本地文档/工具，不提交生成，也不把这类请求当成续跑旧付费任务。

## 保护原成功任务

本用户最新规则：每条新来源在新空白区域使用独立素材副本和全新生成节点；不改旧成功分组任何素材、引用、提示词、参数、连线、名称、位置或结果。已提交任务不因布局错误重做付费；1080也新建独立节点保留480。发现历史改动先列证据与未知，不猜值恢复或盲撤销。

## 默认执行节奏

- **减少工具往返**：已需临时助手时复用常驻Node客户端，稳定的非付费输入合为一次调用；截图直接捕获/缩图，提示词直接全文回读。打开未知菜单、视野或焦点变化立即观察；付费核对与提交保持独立。见 [快速执行](references/speed-workflow.md#工具往返最少化2026-11-16)。
- **续跑直接接未完成阶段**：先读最新用户指令；用 [resume_card.py](scripts/resume_card.py) 从主记录生成小卡片，只展开卡片指向的缺口/矛盾。已有下载先处理本地，不为查已完成任务打开桌面；付费前仍重读政策并核当前UI。同一新任务组素材没变不重做分析、上传、连线或已审证据；新来源在新区建独立组和素材副本，不能复用旧成功组素材。
- **一条下载就进入本地队列**：桌面操作者继续下一项时，用 [finish_downloads.py](scripts/finish_downloads.py) 准备该条审核帧图及原音技术核验，最多两个本地工作并行；不等所有款色下载完才串行收尾。工具输出只代表待审证据，不能自动通过商品或声音。
- **同批独立任务交错推进**：已获授权且无全批审核依赖时，A受理后可配置B；A的480通过后可直接进入其已授权1080，不等B全部完成。付费点击逐条独立进行，每次保留底栏核对与受理身份，不扩大数量或重试额度。
- **一次审核、一次记录**：每条一名审核者负责画面结论，只有疑点才补连续帧或第二人复核；主代理合并结构化结果，不重做全套截图/脚本。同一事件只写主记录，进度/算力/交付从它生成。批量执行细节及命令见 [speed-workflow.md](references/speed-workflow.md)。

## 六阶段执行

| 阶段 | 连续完成的工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1. 准备并分析素材 | 读取任务与授权；用prepare_run.py整理素材和技术证据；用**素材分析提示词**看实际视频/图片，输出01_素材分析.md，再写生成提示词草稿；确认配套原音来源 | 确切源文件与商品匹配；材质依据、镜头动作、结构差异、替换范围和高风险段已分析；未知项写明 |
| 2. 核能力并布置画布 | 当前界面先核实视频编辑模式、视频时长、480原生和单条支持；新区独立组使用新素材副本/新生成节点；同组续跑只补缺失，按用户排版连线 | 实际模型支持；引用列表逐项核对源视频和图片/顺序；布局和云端状态已确认或如实标注 |
| 3. 定稿提示词并提交480 | 根据分析稿和面板实际图序完成**生成提示词**，另存定稿后填入；配置480原生、数量1、比例、时长和预计点数；关闭菜单后独立看底栏再单独点击生成 | 材质在前、引用编号准确、无未填占位；本次生成已获授权，实际参数、定稿和任务身份均记录 |
| 4. 下载并审核480 | 同任务跟进下载；可交错配置其他独立且已授权款色，本地一次准备总览/重点段并对照商品图审核；不重复本款生成 | **通过**且最新任务政策允许才进入本款1080；有瑕疵/不通过/尚未审核不升级，先记问题与修正方案 |
| 5. 政策允许时复用输入做1080 | 保留480结果，复用原始视频、商品图序和提示词；核实正式入口是否保留引用、实际1080选项及数量1；提交一次、下载并独立复核 | 对应480已通过；1080实际像素及商品、动作检查通过；有新问题不标正式通过 |
| 6. 本地原音与交付 | 本地替换生成音轨；核对首中尾时序并听审；保留各阶段文件，一次生成进度、算力明细和交付摘要 | 最终画面、原配音、同步和文件路径均有证据；未知/未完成阶段明确说明，不能只凭文件存在交付为通过 |

### 1. 准备和续跑

- 重启、交接或用户要求先核历史时，按 [resume-and-policy.md](references/resume-and-policy.md) 核最新主记录、用户限制和当前任务。仅用户要求暂停或确需接管桌面时确认原操作者已停止；普通只读监测不打断唯一执行端。区分素材上传、草稿、实际受理、下载、画面审核及听审；本地定稿存在不能证明UI已正确填入。
- 480通过只是质量条件，后续1080和重试还须符合本任务最新授权及`generation_policy`。用户限制按款色不再生成时，已提交或受理未知的该款色仅跟进、下载、审核、合音和归档；此限制不能推广为所有任务永久禁1080。

- 路径指向目录时定位用户指定的确切MP4，不把MP3、上次测试片或最终版当新源片。读取现有任务进度和ID，仅同一新任务组复用其节点、结果和审核证据，只补缺失；原素材不变不重做相同分析。
- 用 [scripts/prepare_run.py](scripts/prepare_run.py) 一次准备，续跑用`--reuse`核验输入、参数、脚本版本及产物签名；工具只准备证据，不自动判定材质/商品/声音合格。调用及计时见 [speed-workflow.md](references/speed-workflow.md)。
- 先使用 [素材分析提示词](assets/material-analysis-prompt.txt) 输出`01_素材分析.md`，再依据分析套用 [生成提示词模板](assets/video-generation-prompt-template.txt) 写草稿；连线后按实际面板图序完成`03_生成提示词_定稿.txt`。两段模板、文件交接和提交检查见 [prompt-principles.md](references/prompt-principles.md)。材质写在最前，区分可见观感与已确认成分；旧鞋和目标鞋型不同需明确重建轮廓，不能只改颜色。
- 本地可并行做技术检查和原音初审；桌面始终只由一名操作者控制。不要为提速省掉素材理解和动态观看。

### 2—3. 画布和480提交

- 先Snapshot确认真实画布与焦点，再按 [generation-steps.md](references/generation-steps.md) 操作。时长和480选项在最早可核实的面板检查，必要时先用原视频建立编辑草稿；不先连完所有图片再检查模型能力。找不到480原生或时长不支持时，记录限制，不擅自升720/1080、拆成多笔或换模型付费。
- 补传用 [画布上传技能](../superdirector-canvas-upload/SKILL.md)。按 [用户排版](../superdirector-canvas-upload/references/canvas-layout.md)：商品图左侧竖排，原视频左下，生成/结果右侧居中，连线从左向右汇入，同任务编组。新来源先在新空白区建独立组，上传独立素材副本并新建生成节点；保护旧成功组全部字段、连线、位置和结果。同组续跑才只补缺失。480/1080各用新节点保留两版。
- 原视频和商品图必须在画布接入同一生成节点；本地图序不等于模型编号。第一条线验证后，仅在端口位置已观察且布局稳定时两条一组操作并集中核对，最终引用列表每项都确认。界面变化立即重新观察。
- 提示词定稿必须基于本次素材分析，最终参考编号按上述实际列表填入；不能将分析指令、空模板或本地图片编号直接当作平台生成提示词提交。480通过后1080沿用已通过的语义约束，不随意重写。
- **关闭参数菜单 → 截图读取实际底栏参数及预计点数 → 单独点击生成**。不把关菜单与付费点击合成盲执行。提交一次就记录身份；状态未知、超时或进度停留时先查原任务，不能再次点击生成。

### 4—5. 两阶段审核

- 下载到原视频同目录并标清货号、阶段、实际设置、北京时间；当前用户明确指定执行包或其他交付目录时按其要求，记录与原片关系。保留原片和所有阶段，不覆盖旧结果。
- 已明确配套原音的下载结果，优先用 [finish_downloads.py](scripts/finish_downloads.py) 一次准备帧图、原音核看片和技术证据；只需画面检查时用 [review_media.py](scripts/review_media.py)。同一文件不连续跑两套全片证据。之后只补疑点，按 [quality-check.md](references/quality-check.md) 核商品、动态和跨帧一致性。
- 480“通过”且本任务最新政策允许时才做1080。完整任务的已授权1080无需反复问开始；用户指定亲自审核则等待其结论。只授权一条测试时遵从范围。有瑕疵或不通过时先给修正方案，**当前没有额外付费授权就不自动重试**。
- 1080复用原始输入，不能默认将480成片作为唯一输入再换鞋。按真实UI标签记录，按钮叫“1080标准”本身不代表不能做平台1080；需核实实际功能和输出尺寸，不用本地拉伸冒充。两阶段和高清入口详见 [generation-steps.md](references/generation-steps.md)。

### 6. 原音、记录和交付

- 按 [local-audio.md](references/local-audio.md) 本地替换原音，不在超级编导尝试加配音。优先视频流复制；不同步先核对动作锚点，不盲目裁尾、整轨变速、循环或冻结。声音来源必须与本次剪辑对应，首中尾听审独立完成。
- 按 [records-and-archive.md](references/records-and-archive.md) 记录一次实际事实，由同一记录生成进度、费用及交付摘要；提交受理、终态及审核完成时更新，不为每张截图重写报表。保留真实参数与提示词和历史错误。同任务ID去重，预计与实扣分列，未知不记0。
- 归档用 [scripts/archive_result.py](scripts/archive_result.py) 校验内容哈希、防覆盖和重复归档；保留原1080下载版及另存的最终原声版。主交付为实际通过的1080最终原声版，附480、1080、说明和费用累计；未达到的阶段如实写明。

## 效率与异常处理

- 操作耗时减少50%是目标；按 [speed-workflow.md](references/speed-workflow.md) 的阶段日志记录操作、平台等待及下载等待，没有同范围完整实测不能声称已达标。现有工具已足够时不重复寻找或安装插件。
- 等待按实际状态调整检查间隔，单次不超过60秒；期间推进下一项独立准备、已有下载的本地审核/原音处理；尚未完成的结果不预判。无需创建跟踪单任务的自动化。
- 首次模型不支持、上传无效、端口变化、费用未知或审核不通过时，先保留证据并定位原因；不以重传全部素材、清空画布或追加付费来试错。用户已授权无响应时自行恢复或重开应用的，先核云端保存与在途任务、保留证据后执行；未授权时不主动重启。重启不解除去重或授权限制，不改变UAC或系统权限。只在新失败或新变更时扩大检查范围。
