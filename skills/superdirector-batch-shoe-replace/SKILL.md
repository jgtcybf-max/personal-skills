# 超级编导批量换鞋

使用用户指定的桌面应用、已登录账户、模型与素材。每帧生成一张，原素材保留，结果独立另存。批量任务应连续推进：首帧检查通过后持续提交，让应用同时生成多张；不要每生成一张才上传下一张。

## 输入与准备

- 一次检查关键帧数量、自然数字顺序、比例，以及商品图是否为同一款鞋的多个角度。颜色或款式混杂且对应关系不明时再询问。参考图超出当前模型限额时，选覆盖鞋型的关键角度并说明。
- 优先附着已打开的窗口；用户已调好的模型、比例、画质和张数直接沿用。只检查一次实际控件并记录，避免重复打开设置。比例跟随源图，混合比例分组；不擅自裁剪或统一缩放。
- 结果默认放源目录同级 `<源目录名>_换鞋结果`，保持源文件 stem、PNG 格式及原顺序。禁止按生成完成时间命名或覆盖未知文件。manifest、预览与报告放任务工作目录，结果目录只放结果图。
- 新任务创建计划；已有本任务 manifest 则续跑，不能重建覆盖：

```powershell
python "<skill>/scripts/files.py" plan --frames "<关键帧目录>" --refs "<商品图目录>" --output "<结果目录>" --manifest "<工作目录>/batch.json" --conversation "<批次名>"
```

商品角度默认按外侧面、内侧面、斜侧面、后面、正面、鞋底、内里排序，其余自然排序。提示词中的角度必须与实际上传顺序一致。不要固定帧数、具体鞋款或历史用户路径。

## 连接与快速执行

连接、持久 REPL 和恢复代码见 [references/desktop-workflow.md](references/desktop-workflow.md)。使用 [scripts/batch.cjs](scripts/batch.cjs)，把 page、run 保存在同一个持久对象内；一个批次只能有一个活动写入者。不要重载 helper、创建多个旧 run 对象交替写同一 manifest。

1. 进入本批次对话，检查已知 DOM 定位器与输入区设置。新任务使用独立对话；恢复任务保留原对话。场景必须是图片1，商品角度为图片2…N。
2. 先生成首帧，`collect()` 下载，目视检查鞋型、双脚透视、动作和背景。通过后调用 `approveFirstFrame(1)`；这是代理的质量检查，无需让用户逐张确认。
3. 用 `pump({maxSubmissions:4,budgetMs:35000})` 连续提交，再接下一轮，直到全部已提交。**一轮结束不等于停工。** 未遇到实际限流就继续填充生成队列；默认不人为限制为一张在途。每4–6张或发现结果完成时收集一次，避免每帧截图、读全页、等生成结束。
4. 参考图通过首个已提交消息的“使用参考图”复用，只替换图片1。禁止每帧重新上传全部商品图或用拖拽调整顺序。脚本核对参考顺序、新场景地址和当前输入区参数后才发送。
5. 全部提交后持续收集；默认最多3张并行下载，生成操作仍通过正常 UI。结果晚于后台完成不影响文件顺序。不要用自动提醒替代本任务的跟进。

## 上传卡住与中断恢复

- 所有上传等待使用**定时轮询**，不依赖后台可能暂停的动画帧。缩略图/blob 预览不等于上传完成，必须有可加载的服务器图片地址。
- `uploading` 表示可恢复的本帧上传，继续当前 handle；不清空重来、不手工修改 manifest。单次等待默认8秒、累计停滞30秒；明确失败可提前返回。
- 上传失败仅自动重选一次，同文件重选前先重置 file input。再次失败返回 `restart-required`，按已授权的本任务范围正常关闭、以普通权限重开、回原对话续跑。最多自动重启两次，不反复点击无响应按钮、不无限等待。
- 用户已要求“关闭重开”时直接执行安全的正常重启，无需重复确认。若存在会被打断的无关生成或草稿，先保留/协调。辅助脚本 [scripts/restart-app.ps1](scripts/restart-app.ps1) 支持 Inspect、Start、Restart；不会强杀进程。只有实际权限拒绝等无法自行解决时才请用户退出一次，并说明具体原因。
- 重启后核对**当前输入区**的模型、比例、画质、张数，避免读到历史消息参数；恢复原对话、加载已提交记录，再 `resumeAfterRestart()`。已提交/已保存帧保持不变，只恢复未提交帧。
- 发送超时先 `reconcile(index)`。`uncertain` 不能自动重发，UI 中出现原标签后按原 message ID 继续。生成失败与上传重试不同：只记录具体编号与原因，核实失败后再决定是否针对该帧重试，禁止重跑整批。

## 换鞋提示词

先看实际图片，描述目标鞋真实特征。按需要改写：

> 仅对【图片1】局部换鞋，将人物双脚原有鞋完整替换为【图片2】至【图片N】所示的同一款鞋，其余图片为同款多角度参考。忠实还原参考鞋的颜色、鞋头、材质、鞋口、鞋帮或靴筒高度、鞋面结构、鞋底和鞋跟。根据原图每只脚的方向匹配透视、比例、遮挡、光照与接触阴影，保持双脚位置和动作。除鞋子及必要的接触阴影外，人物身份、脸、头发、服装、身体、腿部姿势、背景、物品、镜头、构图与色调保持图片1原样。输出单张图片，不拼图，不加文字水印。

原鞋与目标鞋有明显差异时，明确去除旧鞋特征、还原新鞋特征。白底图仅作商品参考，不把最终场景改成白底；不可见的脚不凭空补出。

## 一次核验后交付

```powershell
python "<skill>/scripts/files.py" verify --manifest "<工作目录>/batch.json" --report "<工作目录>/verification.json" --contact-sheet "<工作目录>/results-contact.jpg"
```

核对数量、文件名映射、可解码 PNG、哈希与重复图片。看全部联系表，首帧和可疑帧放大检查鞋头、鞋跟、脚踝衔接、肢体、动作与背景。明显问题针对单帧处理；不重复逐帧执行同一套全量检查。界面2K可能返回不同像素尺寸，按实际记录。

交付时简短报告完成数、顺序规则及结果目录链接，明确尚未完成的编号。保留应用与结果对话，勿关闭附着的 browser。修改本技能时运行 `node --test "<skill>/scripts/batch.test.cjs"` 和技能校验；本地夹具不会创建付费生成。
